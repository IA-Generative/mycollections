# Entretenir

Une collection vit. Sa source change, un document devient obsolète, une ligne est
fausse. Ce qui distingue une collection entretenue d'une collection abandonnée, ce
n'est pas l'absence d'erreurs : c'est que les erreurs sont **signalées**, **corrigées**
et **tracées**.

## Signaler un défaut

Trois motifs : **obsolète**, **erreur**, **manquant**. Un texte libre, et si possible
le document concerné. Sous une réponse de l'assistant qui cite un document, le motif
« document obsolète » ouvre directement le signalement du document cité, avec la
possibilité de déposer une nouvelle version. Le garant prend en compte, puis clôt.

## Proposer une modification

Ouvert à toute personne connectée : une cible (une ligne du tableau, ou un fichier), un
avant, un après, une **justification** obligatoire, une source facultative. Publier ou
refuser revient au garant, et **un refus est toujours motivé**. Chaque proposition
garde son historique.

## Le fil d'avancement

Chaque geste — import, soutien, changement d'état, proposition, signalement — laisse
une ligne dans le fil, signée d'une personne (jamais nommée) ou d'un robot, avec un
détail chiffré. Les abonnés le reçoivent dans la cloche. Un chantier sans événement
depuis trente jours est marqué **en sommeil**, visible de tous : ce n'est pas un
reproche, c'est une information.

## Le geste dans l'outil

Fiche de la collection : onglets **Signaler un défaut**, **Proposer une modification**,
**Historique**. Bouton **S'abonner** pour suivre le fil. Le garant retrouve les
propositions et signalements ouverts en tête de sa fiche.

## Exemple

Sur « Codes NATINF », une contributrice a proposé de remplacer un libellé court prêtant
à confusion par le libellé officiel, en citant natinfo.app ; le garant l'a publiée le
lendemain. Une demande de suppression d'un code abrogé a été refusée, motif : le code
reste cité dans des procédures en cours — il est marqué abrogé, pas supprimé.
